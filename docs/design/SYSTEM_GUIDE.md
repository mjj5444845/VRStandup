# PunchCap 系统设计与实现指南

更新：2026-11-03。本文描述当前架构与后续目标；M5–M9工程流程与Soft Clay Club运行场景已接通，设备集中验收见[清单](../project/DEVICE_TESTS.md)，实际程度以[状态记录](../project/STATUS.txt)为准。

## 系统目标

演员提前在实验室使用 VR 设备完成表演，系统保存动作和声音。
实验时，三维虚拟演员在剧场中重演该片段；观众从自己的座位和视角观看，并按条件与花字互动。
实验员通过电脑控制台推进流程、触发预录回应并记录数据。这个流程称为“录制与异步回放”。
演员表现形式已确认。软件格式、录制接口和会话服务已有 v1 实现；物理同步、研究规则与真实资产继续单独确认。

用户已明确选择三维虚拟演员。演员素材以动作和音频为主；屏幕录像不能替代三维动作记录。
原“演员线上录绿幕视频”的前提不再适用，色键不是正式演员系统的必需环节。
详细方案见[演员录制与回放](PERFORMER_RECORDING.md)，变更依据见[ADR-0011](../decisions/0011-recorded-vr-performer.md)。

## 技术与运行环境

- Three.js 负责剧场、演员、观众和交互；WebXR 负责头显与输入设备。
- Next.js 承载页面；Vercel 提供用户入口，GitHub Pages 发布只读开发看板。开发电脑为 Mac，Windows 11 继续运行实验室会话及私密数据服务。
- 实验室服务由一个 Node 进程提供 HTTPS 页面、WebSocket 和持久日志。
- 参与者与控制台通过同源 `/lab-ws` 通信，实验数据由服务端保存。
- Vercel 上的会话和素材入口先引导进入实验员提供的实验室地址，再进行配对；当前没有将持久日志或私密库部署到 Vercel，也没有开放跨站接口。未来若迁移后台，需另做持久存储与实时服务方案及验收。
- 当前使用 `lab:start` 启动正式模块，默认本机 3002；工程预演可创建会话，正式研究仍等待真人内容、研究确认及设备验收。
- `/study` 与 `/lab` 保留准备工具；`/study/session`、`/lab/session` 为双端预演；`/record` 为录制复查，`/lab/assets` 为私密素材库。
- Windows 与 Quest 3 均需独立实测；Mac 结果不能代替。

## 运行部件

下表包含未实现的模块与候选页面，不表示这些入口已经可用。

| 部件 | 职责 |
| --- | --- |
| 录制端 `/record` | 校准、头部和双手姿态、连续声音、原件导出、缺失/估算/中断与候选模型复查 |
| 参与者端 `/study` | 三维剧场与演员回放、观众、花字、交互、评分和朝向上报 |
| 实验员端 `/lab` | 会话安排、推进流程、回应选择、异常与测量记录 |
| 离线处理工具 | 校验动作和音频、统一坐标与时间、准备段子和回应片段 |
| 实验服务 | 管理会话、分配与消息，写入参与者事件和录音 |

演员素材的录制与观众实验是两个阶段，使用不同数据目录与编号。
演员录音不能与参与者实验时的领夹麦录音混为同一份数据。

条件规则已独立放在 `study/core/conditions.ts`；与演员录制数据格式分开维护。
`core` 只依赖本层，不使用 DOM、Node 或 Three.js；`xr`、`web` 可依赖 core；
`storage` 只依赖本层、core 与 Node；`server`、`tools` 可依赖 storage/core 与 Node，不导入 xr/web；server 的 Next 依赖仅用于页面宿主。其余约束见根目录 `AGENTS.md`。
`npm run check:boundaries` 已检查源码导入方向，包含别名、转发、动态导入与测试文件隔离。
检查工具位于 `scripts/architecture/`，不参与实验运行；该检查不代替运行时权限或 DOM 全局变量检查。
尚未实现的目录和文件按需创建，不放空占位文件。

剧场尺寸与布局按[建模参考](SCENE_REFERENCE.md)准备，先统一坐标与物体中心，再细化座椅、墙面、灯光和装饰。
录制坐标需转换到统一演员根节点，观众的头显坐标仅控制自己的视角。

## 演员素材与回放规则

已建立 take/clip/plan/session v1 格式及旧检查原件转换；后续研究或设备证据需要变更时升版。没有沿用旧 `media.video`、面板比例、色键参数和二维轨迹类型。
至少需要明确以下内容：

- 模型：演员模型、尺寸、骨骼或驱动映射、模型版本及来源。
- 动作：带时间戳的位置与朝向、参考空间、设备能力、有效性和追踪中断。
- 音频：录音文件、真实时长、与动作时间轴的对应关系。
- 校准：舞台摆放原点、方向、地面和身高设置，保留录制到舞台的转换。
- 清单：片段编号、演员编号、文件路径、版本、时长、校验值及确认信息。

时间统一为相对片段起点的毫秒，长度为米；四元数顺序等必须写入格式说明。
动作来源、推算动作与缺失数据应能区分。不要把无效追踪填成原点，也不要把估算的身体当作实录。

回放仍采用音频主时钟：按音频播放进度采样动作，位置插值、朝向插值，再驱动模型。
不得把声音与动作分别按两个普通计时器播放。
暂停、续播和回应切换必须同时作用于动作、音频与花字时间线。
回应使用同一演员的预录动作和声音，需检查切换姿势与续播，避免突然跳位。

写意花字跟随三维手部或模型锚点；间离花字可以放在演员附近或舞台固定位置。
不再通过视频画面的 `(u, v)` 换算手部位置。

## 保留的研究规则

演员表现形式改变不自动改变研究条件与测量方法。以下来自原指南，仍需由正式研究方案确认后实施。

| 条件 | 花字 | 抓取 | 投掷与挂载 | 演员回应 |
| --- | --- | --- | --- | --- |
| A | 无 | 否 | 否 | 否 |
| B | 写意 | 是 | 否 | 否 |
| C | 间离 | 是 | 否 | 否 |
| D | 写意与间离 | 是 | 是 | 是 |

- 笑声安排在各条件中一致；相同时刻事件保持稳定顺序。
- 同屏花字不超过 2 个，默认生存时间上限 5000 毫秒。
- 花字显示区间不与包袱前停顿重叠；间离花字出现在笑声开始后 500–2000 毫秒。
- 写意花字自身不可投掷；最终可投掷取决于花字属性和条件规则两者。
- D 条件按预设回应窗口播放回应，同一段子不超过 2 次；挂载只允许挂在参与者自己身上。
- 分配仍按原指南的 Williams 顺序及段子组轮换思路；具体表需要实验室研究方案支持。
- 现有前后问卷仅为草稿，不能直接替代条件后 VR 问卷；预评分匹配阈值尚未确定。
- 朝向、问卷、评分、异常和实验录音继续保留，并记录统一时间。
- 演员头部参考改为三维回放的头部位置，不能使用旧面板顶端位置替代。

原指南的 V1–V12 校验目标需要按三维素材格式重新映射；停顿、花字上限、演员一致性等规则继续保留。
涉及视频文件、二维轨迹间隔和视频时长的条目不能直接套用。

## 技术验证与下一步

原 S1–S7 是视频面板方案的编号。已经实现的检查页继续保留，后续验收按下表调整。

| 检查 | 当前用途 |
| --- | --- |
| HTTPS 与 WebXR（原 S1） | 仍需验证真实头显安全连接、进入和退出 VR |
| 同端口通信（原 S2） | 继续验证电脑、头显与服务端通信 |
| 视频同步（原 S3） | 保留为音频时钟的技术积累；不能证明三维动作与声音已同步 |
| 去绿幕（原 S4） | 保留为已完成的独立视频技术检查，不再是正式演员回放的前置条件 |
| 进入与音频解锁（调整原 S5） | 验证同次用户操作能够开始 XR 与声音；纯三维演员不要求视频元素解锁 |
| 性能（调整原 S6） | 用三维演员、观众、花字及射线测实际帧率，保留原指南平均帧率不低于头显刷新率 90% 的目标；不再以 1080p 演员视频为负载 |
| 中文面板（原 S7） | 继续验证头显中文可读性 |
| 新增录制与回放验证 | 先检查短动作片段、声音、时间对齐、坐标、缺失追踪和清理 |

当前已有 `/spike/replay` 独立验证页：Mac 使用程序生成的头部和双手轨迹与原创声音，
验证同一片段能同步重演、暂停、继续并切换观众视角。
2026-11-03 已在 Windows 与 Quest 验证模拟回放；另新增 `/spike/record`，真实头部、左右手柄与声音的校准、采集、导出、回放和重新读取回放已由用户实测。
当前只驱动简单几何体；录制原型格式独立，声音采样起点与 XR 预测时间分别保留。物理同步、正式模型映射和中断路径仍需验证。
操作见 [真实录制检查](../guides/13-真实动作与声音录制检查.txt)，具体证据见 [检查记录](../project/VALIDATION.md)。
完整模型、身体推算、表情与口型在基础录制回放通过后逐项评估。

原视频测试的 40 毫秒偏差阈值仍只描述该视频检查。三维动作与声音的验收指标、误差测法与采样频率
需在新验证中明确，不能把旧视频结果记作新方案通过。

## 工程、数据与验收

- 严格 TypeScript，新增依赖固定版本；注释用英文，界面和说明用中文。
- 一个统一帧循环；切换片段、离开页面与重新进入均要释放图形、声音、监听和录制资源。
- 纯逻辑采用有意义的测试；M1 建立分层检查与 Mac/Windows 自动检查，M2 行覆盖率目标不低于 90%。
- 原始动作和声音默认仅保存在本机，采用去身份编号；不会因回放功能而自动放进公开目录。
- 演员素材只有经确认可以公开时才放 `public/study/` 并登记来源与用途；实际私密素材托管方式在服务模块中确定。
- 代码或配置变更运行 `npm run check` 和 `npm run build`；统一检查包含正式格式、轨迹、配置/问卷、协议/状态机、素材/模型映射、真实双端、TLS、持久化与重连测试，数量及覆盖率见最新验证记录；不代替集中设备验收。
- 录制与实验阶段分别记录设备、浏览器、模型、校准和素材版本。Windows、真实录制和头显验收不能用模拟数据代替。
