PunchCap：第一个工作——三维显示检查
更新：2026-10-30

一、这一步要完成什么

让网页真正显示一个会旋转的绿色方块，确认 Three.js 能画出三维画面。
这在专业上叫“基础渲染验证”。它是环境准备中的第一个代码任务。
它不是正式舞台，也不代表头显或完整实验系统已经完成。

二、在 Mac 上打开

打开终端，逐行输入：

cd "/Users/jeffrey/Desktop/VRStandup"
npm run dev -- --hostname 127.0.0.1 --port 3000

如果已经有项目窗口在运行，就不用再开一次。
在浏览器打开：

http://localhost:3000/spike

也可以先打开首页，再点“三维画面检查”。
停止时在启动终端按 Control + C。

三、怎样判断成功

1. 页面出现绿色方块与地面网格，方块会缓慢转动。
2. 点“暂停转动”，方块保持不动，按钮变为“继续转动”。
3. 点“继续转动”，方块恢复转动。
4. 点“重新加载”，方块回到初始姿态，画面仍只有一份。
5. 点“返回首页”，再进入检查页，仍能正常看到一个方块。

可以调整浏览器窗口，确认方块没有被明显拉宽或压扁。
页面会按显示区域重新调整画面；此项仍建议你在自己的浏览器确认。

四、Windows 11 怎么查看

先按“02-Mac到Windows传文件.txt”和“03-Windows11安装与运行.txt”准备项目。
在 Windows 本机安装、检查和构建成功后启动：

Set-Location -LiteralPath "C:\PunchCap"
npm.cmd run start -- --hostname 127.0.0.1 --port 3000

路径是示例，使用你实际保存项目的位置。
在同一台 Windows 电脑的浏览器打开：

http://localhost:3000/spike

再按第三节逐项操作。Mac 成功不代替 Windows 实测。
这些是普通网页步骤；当前不能据此让头显进入 VR。

五、主要代码放在哪里

app/spike/page.tsx
这一页的标题、说明和返回入口。

app/spike/scene-check.tsx
把画面放进网页，连接暂停、继续和重新加载按钮，显示出错提示。
它只在浏览器加载画面代码，避免网页准备阶段误用浏览器功能。

app/spike/spike.module.css
检查页的布局与按钮样式。

study/spikes/scene-preview.ts
创建场景、相机、方块和灯光，更新画面，离开时释放资源。
场景是“画什么”；相机是“从哪里看”；渲染器是“把它画到网页上”。
这些分别对应专业名称 scene、camera、renderer。

关键注释说明了：为什么使用一个更新循环、为什么暂停后调整大小仍需重画、
为什么页面离开或重新加载时必须释放资源，以及如何避免重复创建画布。

六、如果没有画面

页面会显示错误提示，不会一直停在“正在准备”。
可以先点“重新加载”，或确认浏览器的图形加速已开启。
Three.js 当前版本需要 WebGL 2；这是浏览器显示三维画面的能力。
仍不成功时，保留提示文字，并说明操作系统与浏览器，不把失败记为通过。

七、已经检查和还没检查的部分

Mac 的内置浏览器里已看到实际方块，暂停、继续、重新加载和返回后再进入均已检查。
暂停期间的两次截图一致；重新进入后检查到只有一张画布，未读取到警告或错误日志。
当前项目检查内容与最终构建结果见“docs/project/STATUS.txt”。

Windows 11、头显、正式帧率、音画同步和窗口调整仍需各自确认。
本步骤没有安装新工具包，没有提交或推送代码，没有改动旧归档。
技术验证记录见 docs/project/VALIDATION.md，当前进度见“docs/project/STATUS.txt”。
第二步已有独立 HTTPS 与头显检查入口，见 05 说明；实际设备结果仍需单独验证。
