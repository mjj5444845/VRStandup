PunchCap：第四个工作——声音与视频同步
更新：2026-10-30

一、这一步要完成什么

让声音负责计时，让视频跟着声音走，专业上叫“音频主时钟与视频同步”。
这是指南 M0 的 S3 技术检查；先在 Mac 上完成，Windows 和真实头显以后分别实测。
当前使用新生成的测试画面与节拍声，不读取原始录像，不改变问卷和正式研究流程。

通过标准保留指南要求：连续播放 60 秒，所有采样的最大绝对偏差小于 40 毫秒。
没有完成 60 秒、切到后台、发生缓冲或采样中断，都不能记为通过。
这检查的是浏览器媒体时间，不直接测量扬声器和显示屏的物理输出延迟。

二、在当前 Mac 启动

如果已有 3001 检查服务在运行，直接打开网址，不要重复启动。
需要重新启动时，在终端逐行输入：

cd "/Users/jeffrey/Desktop/VRStandup"
npm run check
npm run build
npm run spike:net

在浏览器打开：http://127.0.0.1:3001/spike/media
也可在通信检查入口点击“下一步：声音与视频同步检查”。
保持启动窗口打开；停止时在该窗口按 Control + C。
拿到新版源码后，如果工具包版本清单变化，先执行 npm ci --include=dev。

三、怎样操作

1. 点“准备素材”，等待显示素材已准备好。
2. 点“开始 60 秒检查”。会有轻声节拍，视频每秒闪烁并显示秒数。
3. 保持这个网页在前台，等待 60 秒完成，不切换标签页或最小化窗口。
4. 查看页面显示“通过”“未达到标准”或“未完成”。
5. 点击“下载本次检查记录”，保留完整结果。

当前偏差：视频时间减去音频时间。正数表示画面领先，负数表示画面落后。
最大绝对偏差：整个检查期间出现过的最大偏差，不会因为后面恢复而变小。
画面速度：通常为 1 倍；偏差较大时会暂时减速或加速。
采样方式：显示浏览器是否支持逐帧回调，专业名称 requestVideoFrameCallback。
不支持时改用视频时间读取，并在记录里明确标明。

点击“停止”会结束本次检查并标为未完成。想再试，点击“重新准备”后重新开始。
下载的 JSON 文件含每次采样，可用文本编辑器打开；页面只按每秒展示一行，方便阅读。
记录包含浏览器版本、检查参数、最大值和原始采样，不含参与者资料。
建议保存到项目 output/checks；这类输出和默认文件名已被 Git 忽略，不上传 GitHub。
不要把检查结果、原始资料或私密文件移到 public 文件夹。

四、Windows 11 怎么运行

先按 02 和 03 准备新版源文件及 Node.js。在 PowerShell 逐行输入：

Set-Location -LiteralPath "C:\PunchCap"
npm.cmd ci --include=dev
npm.cmd run check
npm.cmd run build
npm.cmd run spike:net

路径使用实际项目位置。浏览器打开同一个本机网址：
http://127.0.0.1:3001/spike/media

然后按第三节操作。Windows 不需要重新生成素材，也不需要安装 FFmpeg 才能播放。
Mac 的 node_modules、.next 和证书不能当作 Windows 的安装结果。
这一步只供本机访问，不需要为头显开放防火墙端口。

五、测量方法与限制

声音使用 Web Audio 的 AudioContext.currentTime 计时，不用电脑日期或定时器排媒体时间。
视频保持静音，声音只由独立音频源播放，避免双重声音。
准备阶段以静音信号预热声音输出，确认声音时钟实际推进后才允许开始。
同一次点击发起声音环境恢复和视频播放；视频确认可播放后启动音频源。
音频启动时视频已经到达的位置会写进记录，不通过扣除这段偏差修饰结果。

每个新的视频帧记录一次原始偏差，再决定如何调整视频。
画面领先超过 40 毫秒：降到 0.95 倍；落后超过 40 毫秒：升到 1.05 倍。
偏差回到 10 毫秒以内：恢复 1 倍。超过 300 毫秒：跳到音频对应位置。
以上阈值来自系统指南，测试没有放宽它们。最大值包含调速和跳转之前的异常值。
另外设置了 250 毫秒的采样空档保护，防止浏览器暂停采样后仍声称连续检查通过。
这个保护是检查工具的完整性规则，不替代 40 毫秒的研究标准。

声音时钟不等于声音已经从扬声器实际发出的时间；逐帧时间也不等于屏幕的光学测量。
因此本页通过，只能说明当前浏览器中的时间跟随达到本项标准。
正式演员素材、Windows、头显、完整三维场景和物理音画感受仍需另行验收。

六、素材来源与重新生成，平时不用做

public/study/checks/media-clock/clock.mp4：新生成的数字、闪烁条与进度条。
public/study/checks/media-clock/click.wav：同一时间轴生成的节拍声。
public/study/checks/media-clock/fixture.json：参数、字节数和 SHA-256 校验值。
来源和公开许可依据统一登记在 public/study/ASSETS.md。

视频与音频都是 62 秒，留出完成 60 秒检查的尾部余量。
当前 Mac 生成时使用 FFmpeg 7.1，工具来自 PyPI 的 imageio-ffmpeg 0.6.0 固定版本包，
下载后核对包的 SHA-256，只保存到 local_assets/tools，未修改全局工具环境。
FFmpeg 二进制不上传；Windows 直接使用已生成的 MP4 和 WAV。

确实需要重新生成时，先在私密本机备份位置保管旧的三个测试文件，再移走它们。
脚本不会覆盖已有文件。使用自己电脑上可用的 FFmpeg 路径：

Mac：npm run spike:media-fixture -- --ffmpeg ./local_assets/tools/ffmpeg
Windows 示例：npm.cmd run spike:media-fixture -- --ffmpeg "C:\Tools\ffmpeg\bin\ffmpeg.exe"

Windows 路径只是示例，不代表该工具已安装；支持按实际位置替换。
编码工具只参与素材生成，不是网站运行依赖。生成参数和像素、声音源代码都可查阅。

七、主要代码

study/spikes/media-check-rules.ts：计时换算、调速、跳转和严格通过标准。
study/spikes/media-check-rules.test.ts：验证阈值边界、方向、迟滞和未完成状态。
study/spikes/media-check.ts：加载、用户点击启动、逐帧采样、视频跟随、结束和资源清理。
study/spikes/generate-media-fixture.ts：跨平台生成原创测试素材。
app/spike/media/：页面、按钮、结果和本地下载。

本步骤仍是独立技术验证，正式研究模块不会直接导入这些临时代码。
