真实动作与声音录制检查（第一批）
更新：2026-11-03

用途与适用环境

用真实 Quest 头部、左右手柄与麦克风录一小段，再保存、读取和回放。
只显示头部方块和双手测试点，尚未接入正式人物、全身、表情或口型。
当前实测为实验室 Windows 11 加 USB 连接的 Quest 3；Mac 本轮没有实测。
普通电脑可以读取和回放文件，没有 VR 设备时不能录制动作。

准备

1. Windows 在项目根目录执行 npm.cmd run build，再执行 npm.cmd run spike:net。
2. 按 05-第二个工作-HTTPS与头显连接.txt 建立已授权的 USB 3001 端口转发。
3. 在 Quest 自带浏览器手动打开 http://localhost:3001/spike/record。
4. 点击“准备麦克风”，亲自确认浏览器权限，再点击“进入 VR 录制”。
   局域网访问仍需可信 HTTPS；USB localhost 通过不代表局域网信任已配置。

录制

1. 平视前方，扣一次扳机校准。保存地面坐标、原点、朝向和头部高度。
2. 再扣一次开始。自然说几句话，分别移动左右手，不需要卡时刻。
3. 最多 15 秒自动停止，也可提前扣扳机停止。录制期间无需再次扣扳机。
4. 看见“录制结束”后，再扣一次退出 VR。
5. 点击“下载录制文件”，先保存再进行回放。刷新或离开会清空未下载的片段。
   准备后不录制时，可退出 VR 或点击“关闭麦克风并取消准备”。停止录制也会关闭麦克风。

检查与读取

1. 查看有效头部、左手、右手帧数及估算位置数量。
2. 点击“回放真实片段”，试听声音，并观察双手动作。
3. 可以暂停、继续和切换正面/左侧/右侧；切换观察方向不应改变进度。
4. 在“读取已下载的本机录制文件”中选择刚才保存的 JSON，再回放。
   只在当前浏览器读取，不上传。错误或不完整的文件应显示拒绝提示。
5. 发生画面停顿时，回放会暂停在最后可靠进度，需手动继续。

文件与隐私

文件名为 punchcap-recording-check-片段编号.json，含声音、动作、校准、设备能力和异常事件。
声音为单声道 PCM16 WAV，嵌在 JSON 内；动作原始坐标与校准信息分别保留。
真实采集标记为 device-capture，测试文件标记为 test-fixture，不能混作设备证据。
15 秒和 12 MiB 是本次原型的工程限制，不是正式实验或同步合格标准。
不要将自己的录制放进 public/ 或公开仓库；电脑侧放在被忽略的 local_assets/recordings/。
本页不会自动上传，也不会自动备份；Quest 下载目录仍留有一份，请自行保管。

已验证与限制

Quest 已实际进入录制 VR、显示中文校准提示，并完成校准、真实采集、下载、回放和重新读取回放。
首份文件长约 8.74 秒，786 帧，头部和双手全部有效、无估算位置；48 kHz 声音无削波。
首份文件为手动停止；另一次自动结束复测为完整 15 秒、1350 帧、720000 个声音采样，结束原因 limit、无中断，三路姿态全部有效。
更完整的设备复测以 docs/project/VALIDATION.md 最新记录为准。
第二批的中断、麦克风状态与重新开始检查见 14-录制中断与重新开始.txt。
裸手、追踪丢失、设备替换、参考空间重设及麦克风中断保护尚需逐项实机测试。
录制使用声音采样时钟，并保留 XR 预测显示时间和观察时间；两种时钟对应不等于物理同步通过。
麦克风输入延迟、XR 姿态预测和播放设备输出延迟尚未标定；未套用视频的 40 毫秒阈值。
头部高度已保存，但没有做正式人物比例拟合。回放在 Quest 浏览器平面窗口验证，非沉浸式演员播放器。

常见问题

找不到页面：在 Quest 自带浏览器手动输入地址，确认电脑服务与 USB 转发仍在。
麦克风未允许：重新点准备并自行处理浏览器提示，不要让助手代改权限。
有中断提示：保存文件供复查，不能把它计作完整成功录制；重新准备并校准后再录。
声音有数据但听不清：数值不代表音质通过，需实际试听和检查距离、音量及设备。
手部消失：可能缺失或存在多个同侧输入源；不会填零或跨缺失帧插值伪造动作。
