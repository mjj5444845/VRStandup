PunchCap：三维动作与声音回放
更新：2026-11-03

本轮已在指定 Windows 实验室机器和 Quest 3 浏览器分别完成完整回放。
Quest 暂停、切换视角、续播和重载由用户操作；原始报告确认继续次数为 1、六个节拍完整。
暂停时刻不设要求，只需在片段结束前暂停；它不用于测量操作者反应时间。
Windows 后台切换曾出现未报告隐藏状态而绘制停顿的情况，现增加 250 毫秒停顿保护：
保留原始间隔和中断次数，停在最后可靠进度，回到前台后由用户继续。
250 毫秒仅用于识别程序停顿，不是三维同步研究通过线。

一、用途和准备条件

本步骤检查“提前保存一段动作和声音，再由三维模型重演”的基本播放能力。
当前使用原创测试数据：头部、双手、12 秒片段、6 次节拍声。
不需要头显、麦克风或演员录音；声音由你点击“开始播放”后播放。
它不是正式动作捕捉，也不验证全身、面部表情或口型。

灰色躯干只是静态占位。绿色方块表示头部，蓝色球表示左手，金色球表示右手。
模型精修已进入 docs/project/ROADMAP.md 的计划，本轮没有制作精细版模型。

二、Mac 启动

在项目根目录的终端执行，每行输入后回车：

npm ci
npm run check
npm run build
npm run spike:net

已安装且 package-lock.json 没有变化时，不必重复 npm ci。
浏览器打开：http://127.0.0.1:3001/spike/replay
首页也提供“三维动作回放检查”入口。
如果 3001 已运行最新构建，可以直接打开；需要重新构建时先停止原服务，再构建和启动。
停止服务：在启动窗口按 Control + C。

三、Windows 11 启动

在 Windows 本机项目根目录的 PowerShell 中执行：

npm.cmd ci
npm.cmd run check
npm.cmd run build
npm.cmd run spike:net

打开：http://127.0.0.1:3001/spike/replay
依赖和构建必须在 Windows 本机生成，不搬用 Mac 的 node_modules、.next 或证书。
本步骤无需 FFmpeg，也不需要额外模型文件。

四、逐项检查

1. 点击“开始播放”。
   头部和双手应按记录运动；每次节拍时右手到达高点，上方圆灯短暂闪亮。
   共有 6 次节拍，目标时间为 1、3、5、7、9、11 秒。

2. 中途点击“暂停”，观察进度与动作不再前进。
   暂停时可以切换“正面、左侧、右侧”，看到同一个动作姿势的不同角度。
   点击“继续播放”，从原来的进度继续，不从头开始；继续次数增加。

3. 第 6 秒附近会暂时隐藏左手，并显示追踪缺失提示。
   这是特意加入的缺失数据，不是显示错误。系统不把缺失手部移到原点，也不跨缺失区间虚构动作。
   样例中缺失帧为 6.0–6.4 秒；相邻插值区间也保守隐藏，到 6.5 秒的有效帧恢复。

4. 让片段播放到结尾。
   页面应显示 12 秒、6 条节拍记录和本轮回放结果。点击“再次播放”可重新开始。
   “回到开头”停止当前播放并清空本轮记录，不会叠加一份声音。

5. 结束或暂停后，点击“下载本轮记录”。
   保存的是当前浏览器的功能检查数据，包括节拍、继续次数和中断；不自动上传。
   新一轮会清空上一轮记录，需要留存时先下载。

6. 点击“重新加载检查”，或者返回首页后再进入。
   应只保留一份三维画面和一条声音。离开页面会停止声音并释放资源。

五、记录表示什么

片段时间来自 Web Audio 的声音时钟，模型按同一时间读取相邻动作帧并插值。
测试动作的 100 毫秒采样间隔只为演示插值，不是正式录制频率要求。
正式捕捉的数据格式、采样和同步指标需要实测后确定。

“画面提交延迟”：预定节拍时刻之后，程序第一次提交对应进度画面的时间差。
“最大绘制间隔”：播放期间，相邻画面提交之间的最大声音时钟间隔，暂停时间不计入。
这些都是程序层记录，不等于显示器真正亮起、扬声器真正发声或真实演员采集的延迟。
没有减去某个固定基线，也没有把过大的末尾提交时间截成片段长度。

本步骤不套用旧视频检查的 40 毫秒通过线，也不显示研究意义上的“通过”。
完整回放只能说明本轮程序流程结束；真实录制、设备性能、物理输出延迟仍待验证。

六、后台、故障和无声音

切到后台或声音环境被系统暂停时，页面会暂停；回到前台后需点击继续，不自动从后台播放。
此保护仍需在会真正进入后台状态的浏览器实测，不能仅用内置浏览器切换标签的结果替代。

没有声音：确认已点击播放、电脑音量正常、网页声音没有静音。测试声只在上述 6 个时刻出现。
画面无法创建或中断：记录浏览器和错误文字，再点击重新加载检查。
回放卡顿：保留本轮原始记录；不要把切换电脑或重新播放后的好结果覆盖成第一次结果。
