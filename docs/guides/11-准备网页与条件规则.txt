准备网页与条件规则
更新：2026-10-30

一、这轮做了什么

首页仍为开发看板。新增三个可以单独使用的入口：
/study：参与者浏览器准备。
/lab：实验员准备工作台。
/checks：已有技术检查的目录。

这些网页能实际检查和操作，但正式剧场、演员素材与会话服务仍未接通。
准备完成不等于实验验收通过，页面不提供正式开场按钮。

二、启动与访问

在项目根目录安装依赖后：
Mac：npm run build，然后 npm run spike:net。
Windows PowerShell：npm.cmd run build，然后 npm.cmd run spike:net。
打开 http://127.0.0.1:3001/study 或 http://127.0.0.1:3001/lab。
也可以从首页右上角“项目工作台”进入，再使用顶部导航。

3001 是当前同端口技术检查服务，不是正式研究服务。
头显连接必须另外准备有效 HTTPS；电脑本机 localhost 被认可，不表示头显证书已通过。
Windows 电脑操作仍需实验室实测；GitHub Windows 检查的用途不同。

三、参与者准备页

1. 点击“开始浏览器检查”。
2. 查看安全连接、WebGL 2、声音接口和沉浸式 VR 四项结果。
3. 需要时点击“重新检查”。
4. 点击“下载检查记录”，在浏览器下载列表确认 punchcap-browser-preparation.json。

图形检查会创建并释放临时图形环境；声音只检测接口，不实际出声。
检查不进入 VR，不申请麦克风或摄像头权限，也不判断音频输出延迟。
普通 Mac 浏览器没有可用沉浸式 VR 是可能出现的正常结果。

四、实验员工作台

1. 点击 A、B、C 或 D，查看当前设计中的条件差异。
2. 选择花字类别、挂载对象、已回应次数，以及素材是否可投掷。
3. 观察下方显示、抓取、投掷、挂载与回应的允许结果。
4. 点击“检查工作台浏览器”。
5. 实际核对四项人工准备清单；勾选仅代表本页人工记录，不更改开发看板。
6. 点击“下载准备记录”，确认 punchcap-lab-preparation.json。
7. 点击“重置本页准备”，清空清单、检查结果和条件预览。刷新也会清空。

预览规则：A 无花字；B 写意；C 间离；D 同时显示两类并允许额外互动。
B/C/D 可抓取可见花字。写意花字始终不可投掷。
投掷须同时满足 D、间离花字和素材标记许可；挂载仅允许在 D 条件挂在参与者自己身上。
回应仅限 D，每段最多两次；实际回应时间窗留待会话模块检查。
条件预览不会分配参与者、切换真实会话或生成研究顺序表。

五、资料与检查

下载仅保留本机，内容为能力结果、时间、人工清单和条件预览。
没有姓名、参与者编号、录音、浏览器识别字符串或服务器地址；记录带 experimentReady: false。
浏览器可能自行重命名重复下载，请在下载列表确认，不以页面提示代替文件检查。

Mac 页面检查已完成能力检测、下载、条件切换、清单与重置。
执行 npm run check（Windows 用 npm.cmd run check）检查全部代码。
执行 npm run test:core 单独检查条件规则和至少 90% 的核心代码行覆盖率；本轮为 100%。
这不代表全部 M2 已完成，也不能代替正式研究方案确认、Windows 11 或头显检查。
