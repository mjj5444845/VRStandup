演员素材：整理、校验与审核
更新：2026-11-03

来源与格式

正式原件为 punchcap-take-v1，包含毫秒时间、米制坐标、XYZW 四元数、地面/原点/朝向/头高、输入身份、缺失/估算标记、声音和中断原因。
captureLimitMs 保存本轮工程上限；当前正式录制上限 180 秒，旧检查文件上限 15 秒，转换时保留各自上限。
新格式不意味物理同步已通过；这是可版本化的软件约定，研究依据仍单独确认。
前期 punchcap-recording-check-v1 可读取和整理；不从历史归档加载代码或素材。

网页操作

1. 在 /record 先下载原件，再试听、暂停/继续、切换视角；中断或缺失如实保留。
2. 需要检查候选模型时，填模型版本、头部参考高度和节点映射，选择自包含基础 GLB。
   当前支持直接头部/左右手目标映射，缺失时隐藏整个候选模型；不声称完整人体 IK、面部或口型已经录到。
3. 在 /lab/assets 输入实验员访问密钥，读取并校验素材库。
4. 选择本机原件，填新片段编号、演员去身份编号、主段子/回应/练习用途。
5. 默认模型、时间线与同步说明是工程草稿；有真实依据后再导入实际映射和标记。
6. 实际回放并核对后可记录片段审核者、日期和依据。片段审核不等于模型或物理同步审核。
7. 保存到当前实验室电脑的 local_assets/performances/。不是上传到第三方。
8. 修改使用“新版本工作副本”和新编号，原版本不覆盖。

离线操作（Windows，Mac 去掉 .cmd）

生成元数据模板：
node --import tsx study/tools/assets-cli.ts metadata
将模板另存为本机 JSON，填编号、演员、用途、模型映射、时间线与审核说明。

整理原件：
npm.cmd run assets:prepare -- --input 本机原件.json --metadata 本机元数据.json
不要在带空格的路径外省略双引号；两个路径都由本人明确选择。

校验整个私密库：
npm.cmd run assets:verify
每个片段目录包含 manifest.json、motion.json、audio.wav；清单记录声音样本长度及两个文件 SHA-256。
错误文件在播放/会话开始前拒绝，不因扩展名正确就当有效。

同步标记统计

先按研究认可的方法取得至少三次独立的同一实际事件标记，保存：
schema: punchcap-sync-observations-v1
takeId: 对应原件编号
method: 明确测法、设备与标记依据
observations: 每项含 id、motionMs、audioMs、uncertaintyMs

执行：
npm.cmd run assets:sync -- --input 本机标记.json --output local_assets/checks/同步统计.json
程序计算 audioMs-motionMs 的中位偏移，保留所有残差与最保守的不确定度，不自动标为研究合格。
正偏移表示动作事件在声音时间轴上需要向后对齐；播放采样使用 audioMs-offsetMs，不修改原件。
共同点击开始、软件节拍对齐或网络时钟估计不能代替物理同步测量。
最终方法、标记误差及允许偏差由研究方案确认；不套用视频的 40 毫秒线，也不截掉离群样本。

模型与回应

模型映射记录 modelId、modelVersion、映射版本、头部参考高度、头部/左手/右手节点名与局部偏移。
节点必须唯一；候选 GLB 需将纹理和缓冲嵌入文件，不引用任意外部网址，当前最小加载器不启用额外压缩扩展。
演员回应必须同演员、同模型版本、同映射及比例；校准转换后再比较姿态。
时间线包括笑声、写意/间离花字、包袱前停顿和回应窗口；同刻保持文件顺序。
写意不可投掷，同屏花字最多两个、单条最多 5000 ms；不得与包袱前停顿重叠，间离在笑声开始后 500–2000 ms。
这些保留规则按当前设计执行；最终内容和锚点仍需演员审核。

保护原件与验收边界

原始声音、动作、私密库和测试报告不进 Git；公开资产另经确认并登记来源。
工程样例、中断片段、未审核模型/片段和未确认物理同步不能进入正式研究。
M4 目前仅开放工程预演；M5–M9 与集中设备验收完成后才接通正式研究运行。
正式 GLB 的比例、穿模、IK、真实回应衔接和 Quest 效果见集中验收清单，不用自动测试冒充实机通过。
