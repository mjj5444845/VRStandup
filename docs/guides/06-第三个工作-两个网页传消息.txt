PunchCap：第三个工作——两个网页传消息
更新：2026-11-03

指定 Windows 实验室电脑与真实 Quest 3 已通过 USB localhost:3001 完成四次收发，
往返约 9–12 毫秒；Quest 断开后电脑禁用发送，重新连接后恢复。
Windows 开发模式两页未经刷新收到临时文字更新，随后通信计数从 1 增至 2；测试文字已恢复。
Windows 本机 HTTPS/WSS 用临时证书和明确 CA 校验通过；局域网和头显证书信任仍由 05 单独验收。

一、这一步要做什么

在一台电脑打开两个网页：实验员端发送一条测试指令，参与者端收到后自动回复。
这条一直保持连接的消息通道，专业上叫 WebSocket。
网页和消息使用同一个服务端口，对应指南 M0 的 S2 技术验证。

现在先用 Mac 模拟两端，不需要连接头显，也不需要安装证书。
头显连接问题已经按你的要求留待之后处理，不作为本步骤的前提。
本步骤不启动正式实验，不保存研究数据，不播放演员视频。

二、在 Mac 上启动

打开终端，进入当前项目：

cd "/Users/jeffrey/Desktop/VRStandup"

这次版本清单已经变化。当前 Mac 已由助手安装好；换电脑或重新取得源码时先执行：

npm ci --include=dev

逐行执行，每条成功后再继续：

npm run check
npm run build
npm run spike:net

最后一条启动本机通信检查服务，默认使用 3001 端口。
它只允许当前电脑访问，不需要证书，也不能用这个 HTTP 模式对局域网开放。
看到启动成功后保持终端打开，在浏览器访问：

http://127.0.0.1:3001/spike/network

注意是 3001，不是之前三维开发预览的 3000。
普通 npm run dev 或 npm run start 没有接入本步骤的消息服务。
如果使用了它们的网址，可能能看到页面，但无法连接消息通道。

三、按顺序操作

1. 在入口页点击“打开实验员端”，会打开一个新标签页。
2. 回到入口页，点击“打开参与者端”，也保持这个标签页打开。
3. 在实验员端，确认两种角色都显示“已就绪”。
4. 点击“发送测试指令”。
5. 参与者端应显示收到测试指令、已经发出回复。
6. 实验员端应显示收到回复，发送数量和确认数量各增加 1。

页面显示的“往返约多少毫秒”只是本次消息来回花费的时间。
它不是音画同步结果，也不是正式实验的时钟同步数据。

每种角色只保留一个连接页面。如果重复打开，第二个会提示角色已经被占用。
先关闭旧页面或点击旧页面的“断开连接”，再在需要保留的页面点击“重新连接”。

四、再检查断开与恢复

在参与者端点击“断开连接”。
实验员端应显示参与者未连接，“发送测试指令”暂时不可用。
回到参与者端，点击“重新连接”。
两个角色恢复就绪后，再发送一条指令，确认仍能收到回复。

也可以停止服务，检查两个页面显示连接断开。
再次启动服务后，分别在两页点击“重新连接”。本步骤不会自动恢复实验或补发旧指令。
正式系统的自动重连、离线补发和状态恢复将在 M4 实现。

停止服务：在启动终端按 Control + C。
下次代码和工具包都没变时，进入项目后只需 npm run spike:net。
代码变化后重新检查和构建；版本清单变化时先安装工具包。

五、Windows 11 怎么运行

先按 02 和 03 说明传源码、安装 Node.js。
使用 Windows PowerShell，示例项目位置是 C:\PunchCap：

Set-Location -LiteralPath "C:\PunchCap"
npm.cmd ci --include=dev
npm.cmd run check
npm.cmd run build
npm.cmd run spike:net

在同一台 Windows 浏览器打开：
http://127.0.0.1:3001/spike/network

操作与第三、四节相同。Windows 必须自己安装和构建，不能搬用 Mac 的 node_modules 或 .next。
这个本机步骤无需为其他设备开放防火墙端口；本轮 Windows 实测结果已保存在 VALIDATION.md。

六、开发时的自动刷新

自动把代码修改反映到网页，专业上叫热更新或 HMR。
需要改代码时，先停止同一项目已经运行的其他开发服务，再执行：

Mac：npm run spike:net -- --dev
Windows：npm.cmd run spike:net -- --dev

仍使用 3001 的网址。不要同时在同一份源码启动两个开发模式服务。
修改网页文件后检查文字是否自动变化，再发送一条测试指令。
修改服务端文件后，要停止并重新启动服务；它们不会随网页热更新自动重启。
浏览器刷新会清空本页的计数和记录。开发热更新也可能重新连接，不能用它运行真实实验。

七、以后继续检查加密连接和头显

有可信证书后，仍按 05 准备和运行：

Mac：npm run spike:https -- --host 0.0.0.0
Windows：npm.cmd run spike:https -- --host 0.0.0.0

实验员端打开 https://<实际电脑IP>:8443/spike/network/console
头显浏览器打开 https://<实际电脑IP>:8443/spike/network/participant
尖括号中的文字要替换为实际 IP，不要原样输入。
服务会自动使用加密消息通道，专业上叫 WSS，与 HTTPS 页面共用 8443。

同一次检查，两页的地址、电脑名或 IP、端口要一致。
例如两页都用 127.0.0.1，不要一页用 localhost、一页用其他 IP。
当前服务要求网页与消息来自相同地址，不能用第三方网页连接。

Windows 与真实头显的 USB 同端口路径已通过；这不代表局域网证书信任或正式实验协议已完成。
当前检查服务不提供正式身份认证；只用于受控技术验证，不对公网发布。

八、常见情况

连接失败：确认启动的是 spike:net 或 spike:https，网址端口与服务窗口一致。
角色被占用：关闭重复的角色页面，或断开旧页，再重新连接。
端口已占用：停止上次服务；必要时在命令末尾加 --port 3002，两页都换成新端口。
一直等待回复：确认参与者端没有关闭或断开；超过等待时间会提示失败，可恢复连接后重试。
开发服务启动失败：确认之前的开发服务已经停止，不要删除源码或版本清单来尝试修复。

九、代码放在哪里

app/spike/network/page.tsx：打开两个角色的入口。
app/spike/network/[role]/page.tsx：两个角色的页面。
app/spike/network/network-check.tsx：状态、按钮、计数和最近消息。
study/spikes/network-client.ts：浏览器连接、等待超时、手动重连和离开清理。
study/spikes/network-protocol.ts：共用消息格式与严格检查。
study/spikes/network-hub.ts：角色登记、指令转发、回复核对与断开清理。
study/spikes/https-server.ts：网页和 /lab-ws 的同端口处理，保留 Next 的热更新连接。
对应 *.test.ts：配置、消息校验和真实本机连接的自动测试。

这些代码属于独立技术验证，正式实验模块不直接导入。
消息只带测试编号，不带参与者编号、问卷答案或原始资料，不写 data/sessions。
最近记录最多保留 8 条，存放在浏览器内存；截图在 output/checks，不上传 GitHub。
