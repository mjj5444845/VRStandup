# 系统核验与花字提示单

适用：Mac开发电脑、Windows 11实验室电脑。源码更新后在各自电脑安装依赖，不复制node_modules、.next或证书。正式研究仍需真实内容、配置和设备验收。

## 更新与本机核验

先保存当前修改并确认没有与他人工作冲突，再获取项目最新源码。在项目目录执行：

Mac：

```sh
npm ci
npm run check
npm run build
npm run system:verify
```

Windows PowerShell：

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run build
npm.cmd run system:verify
```

成功标志：命令退出码为0、测试无失败、系统核验报告passed=true且列出26份公开资产。该报告不代表头显或研究验收。

## 线上版本核验

先从Git提交记录复制预期的完整40位SHA，然后执行；将示例中的占位文字替换为实际SHA：

```sh
npm run system:verify -- --url https://vr-standup.vercel.app --revision 完整40位SHA
```

Windows使用同一参数，将npm改为npm.cmd。工具只读取公开入口，核对构建SHA、dirty=false、完整素材清单、26份文件及四个页面。旧版本、哈希不一致、非HTTPS、带密码URL或跳转均不会报告通过。

HTTPS证书链错误：保留错误并检查当前网络/受信任证书；不使用关闭证书校验的参数。部署状态成功而此处失败时，应记为“部署成功，线上内容尚未核验”。实验室HTTPS与头显信任另按原指南操作。

## 编辑花字提示单

1. 启动页面后打开`/lab/captions`，也可从实验员工作台进入。
2. 工程模板使用合成片段及已登记PNG。填写每项的表征对象、表演协同、观众补足或评论立场、来源许可；未确认内容留空。
3. W1–W5可多选；混合语义拆成写意和间离两项。组件通过cueId引用时间线，不能把mixed直接作为运行模式。
4. cues沿用毫秒时间、head/leftHand/rightHand/stage锚点和米制offset。当前只支持png-plane；spatial/body-effect会报告未实现。
5. 点击“检查提示单”。无效时间、遮盖停顿、非法投掷、错误锚点会拒绝；未登记图形、缺少说明或渲染能力会列出缺口。来源文字不替代真实授权。
6. 下载提示单和检查报告保存在授权的本机目录。编辑后旧检查结果失效，需重新检查才能下载已验证结构。刷新前先下载，页面不会自动保存。
7. 工程可用不等于正式批准。真实音频、精确时机、演员确认、设备可读性、来源审核和研究批准仍逐项执行。

提示单不会直接提交到素材库、修改片段或上传参考视频。真实内容确认后，按既有素材审核流程把cues用于新的工作副本，保留原件。

验证状态：规则正反测试与页面操作分别记录在VALIDATION.md；Windows/Quest实测不由Mac结果替代。

本机系统构建使用独立的`.next-lab`，Pages静态导出内部使用`.next`并导出到`.next-pages`，最终看板包位于`output/github-pages`。两种构建不再覆盖彼此，可以先build再build:pages；不要在服务使用`.next-lab`时重新运行build，需先停止服务、构建后再启动。源码更新后须在Windows本机构建，不复制Mac缓存。

若旧浏览器已缓存相反的永久跳转，优先打开`http://localhost:3002/study/scene-review`，或对原标签页按Ctrl+Shift+R强制刷新。不能用HTTP 200代替人物、家具、观众实际可见。实验室“准备完整工程素材”会创建`club-flow-v3-human-candidate-`编号的6个合成片段，保留旧`club-flow-`与原始录制；不将旧片段自动批准为新版人体工作副本。
