PunchCap：Mac 开发与运行
更新：2026-10-30

一、这份说明用在哪台电脑

在 Mac 上使用，供你平时编写、修改和查看页面。
Windows 11 实验室电脑的操作请看“03-Windows11安装与运行.txt”。
两台电脑做同一个项目，但安装好的工具包要各自在本机准备。

当前功能完成情况见“00-阅读顺序与当前状态.txt”。这份说明用于现阶段的基础网页。
这一阶段不需要 Vercel，也不需要先购买服务器或域名。

二、确认基础工具

打开 Mac 的“终端”。它就是输入操作指令的窗口。
输入下面两行，每行输入后按回车：

node --version
npm --version

这台 Mac 已检查的结果是 Node.js v22.22.1、npm 10.9.4，不用重装。
如果以后换电脑，可以从官方页面取得对应版本：
https://nodejs.org/download/release/v22.22.1/

三、进入项目文件夹

在终端输入：

cd "/Users/jeffrey/Desktop/VRStandup"

这一步专业上叫“切换工作目录”。上面是目前这台 Mac 的实际路径。
如果以后移动了文件夹，要相应修改路径。

四、安装项目工具包

当前 Mac 已经安装好，可以直接看第五步。
第一次拿到项目，或以后项目的版本清单发生变化时，执行：

npm ci --include=dev

它按照 package-lock.json 里的记录安装工具包，专业上叫“安装依赖”。
--include=dev 表示连开发和检查工具一起安装。
运行期间需要能访问下载服务。出现报错就停下，不要继续执行后面的操作。
这条指令会重新准备 node_modules，不会删除源代码或实验数据。

五、打开本机页面

在同一个项目目录里输入：

npm run dev -- --hostname 127.0.0.1 --port 3000

看到启动成功后，打开浏览器，访问：

http://localhost:3000

成功标志：页面显示“脱口秀的另一种现场”，可以打开两个入口。
首页新增“三维画面检查”，对应第一个代码任务；操作方法见“04-第一个工作-三维显示检查.txt”。
这是方便修改代码的运行方式，专业上叫“开发模式”。
127.0.0.1 表示这一步先只供当前 Mac 访问。
启动窗口要保持打开；关闭它，网页服务也会停止。

停止时，在这个终端窗口按 Control + C。
这里用的是 Control 键，不是 Command 键。

六、改完之后检查

停止开发运行后，在项目目录中依次输入：

npm run check
npm run build

第一条检查常见代码问题，第二条准备正式运行需要的文件，专业上叫“构建”。
每条成功后再执行下一条。出现报错时，保留错误文字供排查。
目前 check 包含静态检查、类型检查和独立配置、通信测试；正式研究逻辑测试以后加入。

七、文件准备放到 Windows 时

请先看“02-Mac到Windows传文件.txt”。
传源代码和版本清单；不要把 Mac 的 node_modules 和 .next 当成 Windows 的安装结果。
Windows 要在自己的电脑上安装工具包、重新构建。

八、这一步不需要填写什么

当前页面不需要密码或其他配置值，不用创建 .env.local。
HTTPS 与头显检查见“05-第二个工作-HTTPS与头显连接.txt”；普通网页预览不需要证书。
录音和正式实验启动还未实现。
不使用头显的双端通信检查见“06-第三个工作-两个网页传消息.txt”，使用单独的 3001 入口。

九、常见情况

1. 提示找不到 node 或 npm：先确认 Node.js 已安装，再关闭并重新打开终端。
2. 提示找不到 package.json：检查是否已经进入第三步指定的项目文件夹。
3. 提示 3000 已被使用：先查看是否有上次打开的项目窗口，在那个窗口按 Control + C。
4. 安装时无法连接：这是工具包下载问题，先保留报错文字；不要随意改版本清单。
